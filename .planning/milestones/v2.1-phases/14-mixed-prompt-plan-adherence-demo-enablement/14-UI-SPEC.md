## Layout Contract (band form)

Inside existing `<fieldset>` legend `Contrato (GenerationRequest)`:

1. Keep `materia`, `topico` unchanged.
2. **Remove** the single `dificuldade` `<select>` (D-09).
3. Add three number inputs (D-09), same `label > input` pattern as `quantidade`:
   - `facil` — label copy: `facil` (count)
   - `medio` — label copy: `medio` (count)
   - `dificil` — label copy: `dificil` (count)
4. Keep `quantidade` editable beside the three counts (D-10) — same `type="number" min="1" max="40"` affordance as today; default may stay `2` or align with a default band split at implementer discretion as long as fields remain independently editable.
5. Soft-warn region: one block below the count/`quantidade` controls (inside the Contrato fieldset or immediately under it), class e.g. `.soft-warn` / `#band-soft-warn`, `hidden` when no warn active. Use warn surface colors above; `role="status"` (not `alert` — non-blocking).

Default counts (locked for predictability): `facil=0`, `medio=2`, `dificil=0` (matches prior default `medio` + `quantidade=2`) unless implementer documents a different zero-sum-safe default that still posts a valid uniform payload on first load.

## Interaction / Payload Contract

Client builds POST `/gerar` JSON as follows (D-12..D-14). Provider/model/reasoning unchanged.

| Situation | Payload shape |
|-----------|----------------|
| **Mixed** — 2+ bands with count > 0 | Include `plano: { facil, medio, dificil }` (non-negative ints). **Omit** top-level `dificuldade`. `quantidade` may be sent as the editable field value (server remains hard gate); prefer documenting that mixed POST may send editable qty even if desynced. |
| **Uniform** — exactly one band count > 0 | Legacy shape: `{ dificuldade, quantidade }` — **no** `plano`. `dificuldade` = sole non-zero band enum (`facil` \| `medio` \| `dificil`). `quantidade` = **that band’s count** (prefer band over editable qty field) (D-13, D-14). |
| **Zero bands** (sum=0) | Still allow POST (D-11). Prefer sending editable `quantidade` + either omit `plano` or send all-zero `plano` only if server accepts; soft-warn visible. Hard fail is server-side. |

Soft validation (D-11): on change and/or submit, compute `sum = facil + medio + dificil`. Show soft-warn when any of: `sum === 0`, `sum > 40`, `Number(quantidade) !== sum`. **Never** `preventDefault` solely for these; never disable submit for soft-warn. Submit still sets button to `Gerando…` / disabled submit only (existing behavior).
