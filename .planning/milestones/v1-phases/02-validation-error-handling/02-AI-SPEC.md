## 1. System Classification

**System Type:** Content Generation (structured extraction)

**Description:**
CLI Python que gera lotes de exercícios de matemática via LLM (OpenAI ou Gemini), retornando JSON tipado com `exercicios[]` contendo `enunciado`, `resposta` e `explicacao`. A Fase 2 endurece a camada pós-geração: validação semântica do lote e tratamento explícito de falhas de API/config, para que só saídas estruturalmente válidas cheguem ao stdout.

**Critical Failure Modes:**
1. Aceitar lote com quantidade diferente da solicitada ou campos vazios/whitespace e imprimir como sucesso
2. Silenciar ou mascarar erros de API (timeout, rate limit, rede, auth) com traceback genérico ou exit 0
3. Misturar logs/erros no stdout, corrompendo o JSON consumível
4. Falhar sem mensagem útil quando `LLM_API_KEY` / `GEMINI_API_KEY` estão ausentes
5. Validação sem identificação de campo/caminho (usuário não sabe o que corrigir)

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** education (math exercise generation for Brazilian Portuguese learners)

**User Population:** Desenvolvedores/estudantes de IA usando o CLI como laboratório; eventualmente professores que consomem o JSON gerado.

**Stakes Level:** Medium

**Output Consequence:** Exercícios inválidos ou malformados podem ser usados em material didático sem revisão humana na v1 — falha estrutural é mais grave que erro matemático pontual (MATH-01 é v2).

### What Domain Experts Evaluate Against

| Dimension | Good (expert accepts) | Bad (expert flags) | Stakes | Source |
|-----------|----------------------|--------------------|--------|--------|
| Completeness of batch | Exatamente N exercícios pedidos | Menos/mais itens que `quantidade` | High | VALD-03, AGENT.md |
| Field completeness | Enunciado, resposta e explicação não vazios (após trim) | Campo em branco ou só espaços | High | VALD-04 |
| Schema presence | Chave `exercicios` presente e lista tipada | Estrutura ausente / tipo errado | Critical | VALD-01, VALD-02 |
| Failure transparency | Mensagem PT com path (`exercicios[i].campo`) e esperado vs recebido | Erro genérico ou silêncio | High | VALD-05, ERR-04, 02-CONTEXT D-05–D-07 |
| Pedagogical structure (soft) | Explicação passo a passo legível em PT-BR | Explicação vazia ou irrelevante | Medium | Domain practice; MATH correctness deferred to v2 |

### Known Failure Modes in This Domain

1. **LLM under-generates:** Modelo retorna 1–2 itens quando `quantidade=3` — Structured Outputs não garante cardinality semântica.
2. **Whitespace placeholders:** Campos preenchidos com `" "` ou `"\n"` passam schema Pydantic `str` mas são pedagogicamente vazios.
3. **Provider-specific empty responses:** Gemini/OpenAI podem devolver `text` vazio ou refusal — deve virar `RuntimeError`, não JSON parcial.
4. **Mixed stdout pollution:** Labels/progresso em stdout quebram `json.loads` do consumidor.
5. **Ambiguous API errors:** Rate limit tratado como "erro genérico" atrasa diagnóstico em lab.

### Regulatory / Compliance Context

None identified for MVP CLI lab. No student PII stored. API keys must never be logged (project security constraint). Educational content in PT-BR — no LGPD trigger beyond not logging secrets.

### Domain Expert Roles for Evaluation

| Role | Responsibility |
|------|---------------|
| Project owner / developer | Label structural fixtures; confirm stderr UX |
| Math teacher (optional, later) | Spot-check pedagogical quality on live samples (Phase 3+ / MATH-01) |

## 2. Framework Decision

**Selected Framework:** OpenAI Python SDK + google-genai + Pydantic v2 (no agent framework)

**Version:** `openai>=1.50.0`, `google-genai>=1.0.0`, `pydantic>=2.0.0`

**Rationale:**
- PROJECT.md / AGENT.md explicitly forbid LangChain, CrewAI, AutoGen in MVP.
- Phase 1 already ships Structured Outputs (`chat.completions.parse` / Gemini `response_json_schema`) with `ExerciseBatch`.
- Phase 2 is validation + error mapping around that pipeline — introducing an agent framework would violate YAGNI and project constraints.
- Dual-provider dispatch (`LLM_API_KEY` / `GEMINI_API_KEY`) already exists in `generator.py` / `generator_gemini.py`.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LangChain / LangGraph | Forbidden by project constraints; hides LLM fundamentals |
| CrewAI / AutoGen | Multi-agent overhead; out of MVP scope |
| Instructor | Cross-provider abstraction overkill; Phase 1 already uses native `.parse()` |
| LlamaIndex | RAG-oriented; no retrieval need |

**Vendor Lock-In Accepted:** Partial — OpenAI + Gemini SDKs are provider-specific at the call site, but `LLM_PROVIDER` / key auto-detect and shared Pydantic models keep the validation layer provider-agnostic.

|---------|-----------|-----------------|

### Common Pitfalls
1. Trusting Structured Outputs alone for cardinality — still validate `len(exercicios) == quantidade`.
2. Logging API keys or full request headers when dumping "raw" payloads.
3. Printing stage labels to stdout — breaks JSON consumers.
4. Catching bare `Exception` and re-raising without `from exc` / useful message (violates ERR-04).

## 4b. AI Systems Best Practices

### Structured Outputs with Pydantic

Use existing models; enrich validators with field-level checks. Example pattern for Phase 2:

```python
from pydantic import BaseModel, Field

class Exercise(BaseModel):
    enunciado: str = Field(..., min_length=1)
    resposta: str = Field(..., min_length=1)
    explicacao: str = Field(..., min_length=1)

def validate_exercise_batch(batch: ExerciseBatch, request: GenerationRequest) -> ExerciseBatch:
    errors: list[str] = []
    if not isinstance(batch, ExerciseBatch):
        raise ValueError("O lote retornado não é uma instância válida de ExerciseBatch.")
    if not hasattr(batch, "exercicios"):
        raise ValueError("Chave 'exercicios' ausente no lote.")
    n = len(batch.exercicios)
    if n != request.quantidade:
        errors.append(
            f"quantidade incorreta: esperado {request.quantidade} exercícios, recebido {n}"
        )
    for i, ex in enumerate(batch.exercicios):
        for field in ("enunciado", "resposta", "explicacao"):
            value = getattr(ex, field, "")
            if not str(value).strip():
                errors.append(f"exercicios[{i}].{field} está vazio")
                # STOP_ON_FIRST mode may break here per D-08 constant
    if errors:
        # user-facing: join plain PT; log layer: [VALIDAÇÃO] + raw JSON dump
        raise ValueError("; ".join(errors))
    return batch
```

Retry on validation failure: **out of scope** (RELY-* deferred). Fail immediately.

### Async-First Design

MVP remains synchronous CLI. Do not introduce async in Phase 2 unless required by SDK — keep surface simple for pytest in Phase 3.

### Prompt Engineering Discipline

Keep `SYSTEM_PROMPT` / `USER_PROMPT_TEMPLATE` in `prompts.py`. Phase 2 should not rewrite prompts except if needed to reduce empty-field failures — prefer validator rejection over prompt churn.

### Context Window Management

N/A — single-shot generation with small N (demo `quantidade=3`).

### Cost and Latency Budget

- Lab usage: few calls per session; prefer fail-fast over retry to avoid token waste (aligns with deferred failover idea).
- Map rate-limit errors clearly so user can back off manually.

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric (Pass/Fail or 1-5) | Measurement Approach | Priority |
|-----------|--------------------------|---------------------|----------|
| Schema / key presence | Pass if `exercicios` present and typed; Fail otherwise | Code | Critical |
| Exact quantity | Pass iff `len(exercicios)==quantidade` | Code | Critical |
| Non-empty fields (trim) | Pass iff all three fields strip-nonempty per item | Code | Critical |
| Error path specificity | Pass if message includes field path and/or expected vs actual | Code + Human spot-check | High |
| Missing API key UX | Pass if clear PT message naming both env vars, exit 1, no traceback dump as primary UX | Code | Critical |
| API error typing | Pass if timeout/rate-limit/network/auth produce distinct user messages | Code (mocked exceptions) | High |
| Stdout purity | Pass if success path stdout is parseable JSON only | Code | Critical |
| No secret leakage | Pass if logs never contain API key values | Code + Human | Critical |
